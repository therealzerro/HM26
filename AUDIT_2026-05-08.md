## Executive Summary

HitMaster is a lottery analytics application built with React Native/Expo, featuring two intelligent recommendation engines (ZK6 and ZK30) that analyse historical draw patterns to generate daily pick slates. The app uses Supabase as its backend, Zustand for state management, and React Query for data fetching. Architecture is solid overall with clear separation of concerns, but several implementation inconsistencies and potential bugs exist between the two engines — most critically around jurisdiction filtering, user authentication, and concurrency safety.

## 1. Engines

### 1.1 ZK6 Engine — `engines/zk6.ts`

**Purpose:** Generates a 6-pick daily slate (K6) for multi-state lottery analysis.

**Signal pipeline:**
1. Fetch `datasets_box` (H01Y–H10Y) and `datasets_pair` (classes 2–11) using `jurisdiction=is.null`
2. Override `draws_since` / `last_seen` from `histories` table
3. Compute BOX (60% frequency + 40% pressure), PBURST (position-specific pair avg), CO (co-occurrence avg), DGC (draw-gap consistency)
4. Three-pass K6 rail selection: Pass 1 real-data only → Pass 2 placeholder fill → Pass 3 relax exclude sets
5. Save `slate_snapshots`; write top-30 pre-rail rows to `daily_intelligence`; PATCH `on_slate=true` for the 6 final picks

**Known inconsistencies:**
- `jurisdiction=is.null` hardcoded (lines 132, 141) — cannot isolate by state
- Horizon weights are fixed (H01Y=0.35 → H10Y=0.02); not renormalised when horizons are missing, unlike ZK30
- Real combos scored 0–1 on BOX; placeholder combos ranked by PBURST only — two separate scoring regimes (lines 760–777, 822–826)
- Bitwise hash for snapshot dedup (lines 1012–1021) — can produce negative values; not deterministic enough for true dedup

### 1.2 ZK30 Engine — `engines/zk30.ts`

**Purpose:** Generates a 30-pick slate for Texas-specific analysis.

**Key differences from ZK6:**
- `jurisdiction=eq.TX` hardcoded in `fetchRaw()` (lines 133, 142) — jurisdiction parameter accepted by `computeSlate()` but silently ignored
- `calculateActiveWeights()` renormalises weights to sum=1.0 for loaded horizons only — better than ZK6's fixed approach
- Soft-deletes prior same-scope K30 snapshot before insert
- **Missing:** no `on_slate=true` PATCH after K30 rail selection (unlike ZK6 line 1140)

## 2. Screens

### `app/(tabs)/index.tsx` — Home / Slate View
- Displays K6 slate for current scope/mode
- Queries `slate_snapshots`, live `histories` ticker (30s refresh), today's results for hit streak
- Paywall: free tier sees picks 1–2 only
- **Issue:** `histories` ticker and stats queries have no jurisdiction filter — pulls all US states every 30s
- **Issue:** Mode state is local only; changing mode does not auto-regenerate
- **Issue:** `energyEmoji()` thresholds (80/65/45) don't align with engine pressure percentiles

### `app/(tabs)/results.tsx` — Results Ledger
- Ledger of all draws for a selected date + ZK6 slate hit overlay
- Two queries: `histories` (all sessions/jurisdictions for date) and `daily_intelligence` (`on_slate=eq.true`, `hit_box OR hit_straight`)
- Hits matched by `jurisdiction + session + date`
- **Issue (post-fix):** `on_slate=eq.true` filter now correctly restricts to final 6 slate picks

### `app/(tabs)/explore.tsx` — Slate Explorer
- Browse today's K6, compare to yesterday, filter by multiplicity/sort
- Manual regen with credit system (PRO: 3/day) — credits tracked via `session_token` in AsyncStorage only
- **Issue:** Yesterday snapshot query missing `deleted_at=is.null` — can show soft-deleted slates (line 75–90)
- **Issue:** `dailyIntelligence` query fetches 2700 rows with no pagination (line 246–284)
- **Issue:** Credit tracking is client-side only; can be reset by clearing AsyncStorage

### `app/(tabs)/intelligence.tsx` — Signal Intelligence
- Historical analysis: hit rates, signal correlation, rank/energy/draws-since distributions
- Queries `daily_intelligence` with `limit=2700`, no jurisdiction filter
- Backfill operation runs on mount — can block on large datasets
- Percentile calculation is ad-hoc client-side; no DB-side aggregation

### `app/(tabs)/account.tsx` — Account / Admin (Hidden)
- Data import (box_history, pair_history, ledger, daily_input)
- Health metrics view
- Manual slate regeneration for all scopes
- Admin-only (role='admin')

## 3. Hooks

### `hooks/useAuth.tsx`
- **Critical:** Default user is hardcoded to `role='admin'` (line 19)
- **Critical:** If stored user has no ID, forces `role='admin'` (lines 33–34) — privilege escalation
- `purchaseSubscription` and `restorePurchases` are placeholder stubs with 1s delay — no real IAP/Stripe integration
- Role can be set arbitrarily client-side; no server validation

### `hooks/useScope.tsx`
- Persists `scope` to AsyncStorage
- Defaults to `'allday'` on first launch
- No validation of stored scope value before use

### `hooks/useDataIngestion.tsx`
- Handles import, health metrics, slate regeneration, hit detection
- Hit detection matches `result_digits` vs `comboSet`; updates `daily_intelligence.hit_box/hit_straight`
- **Issue:** Imports `computeSlate` from `zk6` only (line 8) — no path to trigger ZK30 regen
- **Issue:** `excludedCombos` not cleared between regen calls; prior exclusions can persist across sessions
- **Issue:** DELETE then INSERT for `daily_intelligence` is not atomic — concurrent regen can wipe newly written hit flags

## 8. Bug Registry

### 🔴 Critical

**BUG-01 — ZK30 Jurisdiction Hardcoded**
- `engines/zk30.ts` lines 133, 142, 279–315
- `fetchRaw()` ignores jurisdiction parameter; always queries `TX`
- Cannot switch jurisdictions dynamically; silent data loss if TX deactivated
- **Fix:** Add `jurisdiction` parameter to `fetchRaw()`; pass through to both queries

**BUG-02 — Default Admin Role**
- `hooks/useAuth.tsx` lines 19, 33–34
- All new users default to `role='admin'`; role can be set arbitrarily client-side
- Full privilege escalation for any user
- **Fix:** Default to `'free'`; validate role server-side via Supabase RLS + JWT claim

### 🟠 High

**BUG-03 — on_slate Not Set for ZK30 Picks**
- `engines/zk30.ts` lines 1136–1176
- ZK30 does not PATCH `on_slate=true` for its 30 final picks, unlike ZK6
- Results screen and any `on_slate`-filtered query cannot distinguish K30 hits
- **Fix:** Mirror the K6 PATCH block after K30 rail selection

**BUG-04 — DELETE→INSERT Race Condition**
- `engines/zk6.ts` lines 1118–1133; `engines/zk30.ts` lines 1159–1173
- Non-atomic delete then insert for `daily_intelligence`; concurrent regen wipes hit flags
- **Fix:** Use PostgREST UPSERT (`on_conflict`) or wrap in a Supabase RPC transaction

**BUG-05 — Snapshot Hash Collision**
- `engines/zk6.ts` lines 1012–1021
- Bitwise hash of JSON string can produce negative values; mode not included in input
- Dedup silently fails; duplicate snapshots not soft-deleted
- **Fix:** Use `crypto.subtle.digest('SHA-256')` or `uuid()`; include mode in hash input

**BUG-06 — Client-Side Credit Enforcement**
- `app/(tabs)/explore.tsx` lines 144–177
- PRO daily regen credits tracked in AsyncStorage only; no server-side validation
- **Fix:** Track in `audit_logs` or `slate_credits`; enforce server-side via RLS policy

### 🟡 Medium

**BUG-07 — No Pagination on Large Queries**
- `app/(tabs)/results.tsx:131`, `app/(tabs)/explore.tsx:246`, `app/(tabs)/intelligence.tsx`
- Queries fetch 500–2700 rows in one shot; mobile memory/network impact
- **Fix:** Add offset/limit with infinite scroll or fixed page sizes

**BUG-08 — ZK6 Jurisdiction Filter is Global-Only**
- `engines/zk6.ts` lines 132, 141 — `jurisdiction=is.null`
- Cannot generate jurisdiction-specific ZK6 slates
- **Fix:** Accept optional `jurisdiction` parameter; union null + explicit rows or filter by jurisdiction

**BUG-09 — Scoring Divergence: Real vs Placeholder Combos**
- `engines/zk6.ts` lines 760–777, 822–826
- Real combos normalised 0–1 on BOX; placeholders ranked by PBURST only
- Placeholders can outrank low-BOX real combos in edge cases
- **Fix:** Apply uniform normalisation to both pools; use PBURST as tiebreaker only

**BUG-10 — Yesterday Snapshot Missing `deleted_at` Filter**
- `app/(tabs)/explore.tsx` lines 75–90
- Can surface soft-deleted yesterday slates
- **Fix:** Add `&deleted_at=is.null` to query

**BUG-11 — Timezone Handling Ad-Hoc**
- Multiple files — `getTodayET()` uses browser locale + hardcoded 4h offset
- Daylight saving transitions cause off-by-one day errors
- **Fix:** Use `date-fns-tz` or `luxon`; store all timestamps UTC; convert on display

**BUG-12 — `histories` Queries Without Jurisdiction Filter**
- `app/(tabs)/index.tsx` lines 388–392, 400–406; `app/(tabs)/explore.tsx` lines 93–102
- Fetches all US states every 30s; unnecessary load
- **Fix:** Filter to configured/monitored jurisdictions from `app_config`

**BUG-13 — `bestOrderFor` Pair Key Mismatch**
- `engines/zk6.ts` line 1002; `engines/zk30.ts` line 1046
- `sortedPair()` and `normalizePairKey()` may produce different key formats (e.g., `"12"` vs `"{1,2}"`)
- Lookup misses → `bestOrder` silently defaults to original combo
- **Fix:** Log pair key formats on first fetch; add defensive fallback; normalise at import time

### 🔵 Low

**BUG-14 — DGC Zero for Single-Hit Combos**
- `engines/zk6.ts` line 388
- Combos with exactly 1 historical hit get DGC=0; treated same as never-drawn combos
- **Fix:** Return configurable low-consistency value (e.g., 0.3) for single-hit combos

**BUG-15 — Energy Emoji Thresholds Don't Match Engine Output**
- `app/(tabs)/index.tsx` lines 31–42
- Emoji thresholds (80/65/45) don't correspond to engine pressure percentile scale
- **Fix:** Align thresholds with pressure percentile output from engine; document mapping

**BUG-16 — Loose TypeScript `any` in Snapshot Fields**
- `app/(tabs)/index.tsx` line 278 — `horizons_present_json: Record<string, any>`
- Unsafe property access; refactor risk
- **Fix:** Export explicit `EngineMetadata` type from `types/core.ts`

**BUG-17 — No Error Boundary on Pull-to-Refresh**
- `app/(tabs)/index.tsx` line 411
- `handlePullRefresh()` can throw unhandled rejection on network failure
- **Fix:** Wrap in try/catch; show toast on error

## 9. Data Flow Diagram

```
Admin / Account Screen (role='admin')
  ├── Import: datasets_box, datasets_pair, histories
  └── Trigger Regen
        ├── ZK6: computeSlate(scope, weightsKey)
        │     ├── Fetch: datasets_box (H01Y–H10Y), datasets_pair (classes 2–11)
        │     ├── Override: histories (draws_since / last_seen)
        │     ├── Compute: BOX, PBURST, CO, DGC per combo
        │     ├── Select: K6 (6 picks) via 3-pass rails
        │     ├── Save: slate_snapshots
        │     └── Write: daily_intelligence (top 30 pre-rail)
        │               └── PATCH on_slate=true for 6 final picks
        │
        └── ZK30: computeZK30Slate(scope, 'TX')
              └── Same flow; K30 (30 picks); TX hardcoded

Live Results (histories, 30s refresh)
  └── Hit Detection: match result_digits vs comboSet
        └── PATCH: daily_intelligence.hit_box / hit_straight

Home Screen
  └── Display: slate_snapshots[scope].top_k_straights_json[:6]
        └── Paywall: free tier locked at rank > 2

Results Screen
  ├── histories (ledger for selected date)
  └── daily_intelligence (on_slate=true & hit=true → ZK6 hits only)

Explore Screen
  ├── today's K6 + yesterday snapshot
  └── Manual regen (PRO: 3/day, client-enforced)

Intelligence Screen
  └── daily_intelligence (2700 rows, hit rate / signal analysis)
```
