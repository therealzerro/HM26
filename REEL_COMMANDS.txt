================================================================
HITMASTER REEL COMMANDS — copy/paste reference
================================================================
Rule: this file is ALWAYS updated when a reel command is added or
changed. Every command has a description. (Last updated 2026-07-27 —
Anchor intro now opens every reel: All-Day 28.1s, verify 14.4s;
reel:check validates the intro and falls back safely if it's missing)


----------------------------------------------------------------
DAILY RUN PROCEDURE (every morning, in this order)
----------------------------------------------------------------

STEP 1 — TERMINAL A: open the port for the day (leave it running)

    npm run start-tunnel

    Starts the app dev server on port 8081 with the tunnel. The
    reel renderers drive the real app through this port, so it
    must be up BEFORE any reel command — and you just leave this
    terminal open all day. If reels fail with "connection
    refused" or the render hangs on a blank page, this terminal
    is the first thing to check.

STEP 2 — ADMIN APP: run the Full Daily Workflow (before 8:30 ET)

    (in the app: Admin → Dashboard → ⚡ Full Daily Workflow)

    Not a terminal command — but it MUST finish before Step 3:
    it grades yesterday (the verify reel's receipts) and builds
    today's boards (the All-Day reel's content). Reels run
    before the workflow = stale or missing data.

STEP 3 — TERMINAL B: build + publish the day's reels

    npm run reel:verify
    npm run reel:allday

    Run in that order (receipts first, then today's drop).
    SUCCESS = each command ends with "✔ registered — visible in
    Admin → Reels" per reel. FAILURE = red ABORT/error text in
    the terminal — nothing uploads on a failure, and a zero-match
    day makes reel:verify abort on purpose (skip it, no receipts
    that day).

STEP 4 — PHONE: post from Admin → 🎬 Reels

    Pick target → caption's already drafted (Pro carries the
    numbers) → Save to Photos + Open Group → attach, paste, post.

NOTE: if you replaced any endcard/carrier since yesterday, run
`npm run reel:check` between Step 2 and Step 3.


----------------------------------------------------------------
DAILY DRIVERS (the two commands in Step 3, in detail)
----------------------------------------------------------------

npm run reel:allday

    Makes BOTH All-Day reels (Pro + Free) for TODAY: renders the
    grid + six signal-modal tap-through from the live app,
    assembles the 28.1s reels (Anchor intro, body, endcard outro,
    VO + hum bed), writes 9:16 + 1:1 cuts + contact sheets to
    assets/marketing/allday_reels/, then AUTO-UPLOADS the finals
    to the app — they appear in Admin → Reels within seconds,
    with fresh daily captions (real numbers in the Pro caption
    only). Every cut carries the SLATE STAMP: a burned-in chip
    ("TODAY'S DATA DROP / MON · JUL 27 · ALL-DAY") generated
    automatically from the slate date — never edit it by hand,
    it always matches the data on screen.


npm run reel:verify

    Makes YESTERDAY's "Receipts" verification reel (14.4s): renders
    the verification breakdown from the live app, assembles with
    the Anchor intro + endcard, writes to
    assets/marketing/verify_reels/, then AUTO-UPLOADS to
    Admin → Reels with a fresh caption. Aborts on purpose if
    yesterday had zero verified matches (no receipts = no reel).
    Carries its own green SLATE STAMP ("✓ VERIFIED RESULTS /
    SUN · JUL 26") — same auto-generated chip, receipts flavor.


----------------------------------------------------------------
PANEL BUILD (only when panel artwork is added or replaced)
----------------------------------------------------------------

npm run panel:build

    Preps the rotating promo panels that appear at the bottom of
    each pick-detail modal. Drop new artwork into
    assets/marketing/panels/, run this, then npm run reel:check.

    The panel is a real part of the app screen, not something
    pasted onto the video — so it shows up in reels simply
    because the camera sees it. It is switched ON only while the
    reel renderer is driving the app: subscribers never see a
    panel in the product.

    Each panel is cropped to its artwork band automatically, so
    the band's shape is flexible and anything below it (like a
    generator watermark) is discarded. Edges are feathered, so
    the panel's own background colour doesn't have to match the
    app — full-bleed artwork works fine.

    A different panel shows on each of the six modals; which one
    leads rotates by date, so every panel gets the opening slot
    once every six days. Adding a seventh panel needs no code
    change. A missing panel is skipped with a warning — it never
    blocks the daily run.

    IMPORTANT: panel copy is cleared by hand and locked to the
    file. If artwork is replaced, reel:check FAILS until the copy
    is re-read and re-approved — that's deliberate, it's the only
    thing stopping unreviewed words reaching a reel. To approve:
    npm run panel:build -- --print-hashes, then paste the new
    hash into scripts/panel-config.ts.


----------------------------------------------------------------
ENDCARD BUILD (only when a motion file or copy changes)
----------------------------------------------------------------

npm run endcard:build            (all variants)
npm run endcard:build allday_pro (one variant)

    Builds an endcard from a TEXT-FREE motion clip plus its copy
    in scripts/endcard-config.ts. The wordmark is rendered fresh
    at full 1080x1920 and laid over the motion, so the type is
    razor sharp instead of being stretched up from 720.

    This means COPY IS NO LONGER AN ASSET: to change a line, edit
    the string in endcard-config.ts and re-run — no new video
    generation. Midday/Evening reuse the SAME pro motion file, so
    session endcards cost nothing but a config entry.

    Safe to re-run: a variant whose motion file hasn't been
    delivered is skipped, and the first time a hand-made endcard
    is replaced it's preserved as <name>_baked_backup.mp4.
    Run npm run reel:check afterwards.


----------------------------------------------------------------
CAPTION TOOLS (no video work — safe anytime)
----------------------------------------------------------------

npm run reel:publish -- allday --preview

    PRINTS today's All-Day Pro + Free captions without writing
    or uploading anything. Use it to see what will ship.


npm run reel:publish -- verify --preview

    Same preview for yesterday's verify-reel caption.


npm run reel:publish -- allday --captions-only

    Regenerates and SAVES fresh captions onto today's All-Day
    reels already in Admin → Reels — does NOT re-upload video and
    does NOT reset a reel you already marked posted.


npm run reel:publish -- verify --captions-only

    Same caption refresh for yesterday's verify reel.


----------------------------------------------------------------
ASSET CHECK (run after replacing any endcard or carrier)
----------------------------------------------------------------

npm run reel:check

    Preflight-validates every endcard + carrier against the
    assembler's contract BEFORE you build: catches corrupt/
    placeholder files (GitHub renames!), missing audio, too-short
    video/audio, voiceover that would get cut mid-phrase, weak
    bolt-crack audio, and low-resolution sources. Also test-
    renders the slate stamp chip so a broken stamp renderer
    fails here, not mid-assembly. It also FETCHES each promo
    panel from the running dev server — a panel can be sitting
    on disk and still not be served, which would quietly produce
    reels with no panels and no error anywhere. ⛔ = do not
    assemble; ⚠️ = works but quality note. Takes ~20 seconds.

    NOTE for new carriers/endcards/VOs: none of them carry a
    date — the slate stamp is overlaid at assembly time, so
    rotating variations stay evergreen. Never bake a date, day
    name, or "today" visual into a generated asset.

    MULTI-PART CARRIERS: if a VO comes back as two ~10s clips,
    just drop them in as allday_pro_carrier.mp4 +
    allday_pro_carrier_pt2.mp4 (…_pt3 etc. if needed) — the
    pipeline joins them automatically, in order, before
    assembling. Nothing else to run. reel:check validates the
    JOINED track, so a VO that overruns the ceiling only after
    the join is still caught here. Works for verify too.


----------------------------------------------------------------
RE-PUBLISH / BACKFILL (when files exist but the app row is wrong)
----------------------------------------------------------------

npm run reel:publish -- allday

    Re-uploads today's All-Day finals from assets/marketing/ and
    re-registers them in Admin → Reels. NOTE: resets the reel's
    status to "ready" and rewrites the caption (a re-publish is
    treated as a new reel).


npm run reel:publish -- verify

    Same re-upload for yesterday's verify reel.


----------------------------------------------------------------
PAST DATES (add a date stamp to any command above)
----------------------------------------------------------------

Date format is YYYYMMDD. Examples:

npm run reel:publish -- allday 20260726 --preview

    Preview the captions the 7/26 All-Day reels would get.

npm run reel:publish -- verify 20260725

    Re-upload the 7/25 verify reel (files must still exist in
    assets/marketing/verify_reels/).

npx tsx scripts/assemble-allday-reels.ts 20260726

    Re-assemble the 7/26 All-Day reels from an already-rendered
    body (advanced — normally reel:allday does this for you).


----------------------------------------------------------------
GOOD TO KNOW
----------------------------------------------------------------
- Everything uploaded lands in the app: Admin → GROWTH → 🎬 Reels.
- Phone posting: Save to Photos + Open Group, attach from camera
  roll inside Facebook. Web: Prepare Video → Save/Share.
- Uploaded reels auto-delete from storage after 30 days.
- Captions rotate style automatically every day; re-running the
  same day gives the same caption.
