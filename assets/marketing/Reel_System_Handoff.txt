⚠ CHANGED 2026-07-29 (MKT-26) — VARIANTS NO LONGER ALWAYS SHARE ONE BODY.

each session scope renders TWO bodies.

  ui_<scope>_<stamp>.mp4           full-fidelity — Pro (unchanged name)
  ui_<scope>_redacted_<stamp>.mp4  digits masked — Free sessions only

WHY THIS IS ENFORCED AND NOT LEFT TO CONVENTION. Before MKT-26 the assembler
resolved ONE body per scope, outside the variant loop. Switching the free
session variant on without changing that would have handed the full-fidelity
board to the free group — and nothing would have caught it, because the carrier
resolves, the endcard resolves, the stamp renders, the contact sheet generates
and preflight reports 0 fail. Every one of those validates an ASSET; the defect
was inside the capture. So each body now carries an `hm_reel_redacted` tag in
its own container metadata (same mechanism as MKT-18's date tag) and the
assembler asserts it against the kind consuming it. A body with no tag is
treated as full-fidelity, which means a renamed copy cannot pose as redacted —
a stray copy of the Pro body was in fact caught this way on 2026-07-29.

row, bare 3-digit leaves, the {•••} brace set chip on BOTH grid and modal, the
position boxes, pair LABELS and pair PROSE. Verified non-recoverable across all
seven digit-bearing surfaces at ten settling frames.
KEPT: energy, ZK6 confidence, all four signal percentages, heat badges,
jurisdiction counts, panels, and the full prose structure.

5. THE CAPTION SYSTEM (matters for any copy you propose)
--------------------------------------------------------------------------------
Captions are generated at publish time by a template engine — not written
per-day by hand, not AI-freestyled.

  ROTATION — each content kind has 8 template families. The day's date picks
  the template deterministically: a different style every day, never the
  same style on two kinds the same day (protects the duplicate-caption
  rule), and re-running the same date reproduces the same caption exactly.
  Kinds today: allday_pro, allday_free, verify (free draft), verify_pro,
  midday_pro, evening_pro, midday_free, evening_free. The three PRO slate kinds
  are spaced so they never
  draw the same template family on the same day — a subscriber who sees the
  Midday, Evening and All-Day posts reads three different messages.

  THE NUMBERS POLICY (operator ruling, absolute):
  - PRO captions ONLY may contain real performance data: verified counts,
    state attributions, STRAIGHT MATCH callouts, 30-day totals. These are
    computed fresh from the verified results record (yesterday's board
    checked against actual observed draws — never cached flags).
  - FREE captions are QUALITATIVE. They may DESCRIBE matches creatively,
    but only in descriptor language — scale words ("a verified MATCH" /
    "multiple verified MATCHES" / "a stack of verified MATCHES"), spread
    words ("across several state boards" / "from coast to coast"), and
    STRAIGHT MATCH presence ("one of them a dead-on STRAIGHT MATCH").
    Never counts, never state names. The video shows the receipts; the
    caption text a classifier reads stays clean. Gambling-adjacency
    protection — do not ask for exceptions.
  - THE VERIFY REEL CARRIES TWO DRAFTS (one reel, two rooms): a free-group
    draft (qualitative description, above) and a pro-group draft (full
    precision). In the operator's Reels screen, switching the target
    between Free and Pro loads the matching draft automatically.
    Example, same day (7/24):
      FREE: "Grade day: 7/24 closed with a stack of verified MATCHES from
             coast to coast — one of them a dead-on STRAIGHT MATCH. Pull
             your state's results and compare."
      PRO:  "Graded in full: 7 MATCHES across 7 states on 7/24 — including
             a STRAIGHT MATCH in PA. 🧾"

  VOICE RULES for any template you propose:
  - The product noun is "signals". Always. (Never picks/plays/numbers.)
  - Match vocabulary: MATCH / BOX MATCH / STRAIGHT MATCH. Never "hit(s)",
    never "partial match", never win/won/winning.
  - No guarantees, no urgency hype ("don't miss out", "act now"), max ~2
    emoji, viewer-friendly plain language — receipts-and-record energy,
    not hype.
  - Free All-Day captions never pitch Pro. Pro captions never mention
    pricing.
  - Approved coverage claims: "40+ states & provinces" or "39 tracked
    feeds" (never "40+ jurisdictions").

  PROPOSING NEW TEMPLATES: deliver lines as text following the rules above,
  tagged by kind (pro / free / verify). Engineering adds them to the
  registry — template count per kind can grow beyond 8; rotation adapts.

  New content types (future reels/posts) get their own registry entry with
  the same contract. The realNumbers flag is structural: a non-pro template
  physically cannot access performance data.

  ⚠ CHANGED 2026-07-29 (MKT-20) — THE PAIRING IS NO LONGER DERIVED FROM THE
  FILENAME. It used to be: the joiner read part 1 and went hunting for
  "<that name>_pt2.mp4". It is now declared per kind in
  scripts/carrier-config.ts, because rotating part 1 breaks derivation — an
  alternate opening would send it looking for a part 2 that will never exist.
  What that meant in practice is worth knowing, because it is why the rule
  changed rather than being patched: the unpaired carrier would resolve at
  ~10s, fall below the overlap threshold, silently switch the reel to hum-bed
  mode, and PUBLISH a reel with roughly half its narration replaced by hum.
  Nothing would error and preflight would pass.
  For you this is simpler, not harder: an alternate part 1 can be named
  anything, and it does not need its own part 2. What you must state on
  delivery is which KIND and TIER it belongs to.

  Rules:
  - A 0.35s breath is inserted automatically at each part boundary, on
    top of whatever silence the parts already carry. You do NOT need to
    pad the end of part 1 or the start of part 2 — start part 2's first
    word promptly and the joiner supplies the pause. (The 7/27 delivery
    started part 2 at 0.2s, which left only a 0.4s gap after part 1's
    last word and read as crowded at this voice's pace.)
  - **The ceiling applies to the JOIN, not to each part.**
    ⚠ CORRECTED 2026-07-28 — v1.5 said "part 2's final word must land by
    ~7.0s of part 2 (10.0 + 7.0 = the 20.0s carrier ceiling)". That is
    arithmetically wrong: 10.0 + 7.0 is 17.0, and it cost you ~2.6s of
    usable narration. Measured against the code:

        part 1                 10.005s   (generator's 10s preset)
        + breath                0.350s   (inserted automatically)
        + part 2               10.005s
        = joined file          20.360s
        assembler fade begins  20.010s
        so the LAST WORD must land by ~9.65s OF PART 2.

    In other words a ~10s part 2 may use essentially its full length.
    The 20.0s figure is the target; 20.5s is the hard fade. Preflight
    measures the JOIN, so an overrun is caught before assembly.

  - ⚠ THAT EXTRA ROOM IS NOT SPENDABLE. The correction is real against
    v1.5's arithmetic but NOT against what the generator delivers: this
    voice runs ~35% longer than scripted timings. public_carrier_pt2's
    last word was written for 6.9s and came back at 9.32s, so against the
    corrected ~9.65s ceiling the delivered pair has ~0.33s of ACTUAL and
    ~0.25s of SCRIPTED headroom. The public carrier is effectively FULL.
    Do not plan a longer CTA on the strength of the corrected number.
    Practical rule (content agent, 2026-07-28): script carrier VO to about
    70% of whatever the real ceiling is, and treat any scripted timing as
    advisory until it comes back measured.
  - HOW MUCH ROOM IS ACTUALLY LEFT: on the current public pair the last
    word ends at 19.694s of the join, 0.32s before the fade. That margin
    is set by the CARRIER, not the body — a LONGER body does not consume
    it. The risk runs the other way: if a body render comes in SHORTER
    than ~18.4s the fade moves earlier and the margin inverts. Safe band
    for the delivered pair is a body of 18.4s–20.0s (today: 19.0s). If a
    future capture leaves that band the fix is a shorter part 2, never a
    trimmed audio tail.
  - A continuation the config does not declare is a hard FAIL, not a silent
    skip. Under derivation this was "a _pt3 without a _pt2"; under explicit
    pairing it is any `<part1>_ptN.mp4` on disk that carrier-config.ts does
    not list. Either way the reason is the same — dropping it would leave a
    hole in the narration — and either way it blocks the run rather than
    shipping quietly.
  - ⚠ EVERY PART 1 IN A ROTATION SET MUST BE THE SAME LENGTH (MKT-20).
    Part 2's offset in the join is part 1's FILE duration, not its voice-end,
    so a variant delivered at 9.2s or 11s moves the ceiling on the mornings
    it plays and looks perfect on the others. Preflight FAILS on a mismatch,
    measured against the incumbent rather than a hardcoded 10.005s.
  - ⚠ THE 0.35s BREATH IS NOT THE AUDIBLE PAUSE. It is what the joiner
    INSERTS; a listener hears 0.35s plus whatever tail part 1 already carries.
    Across the current All-Day set that lands between 0.586s and 0.777s. Both
    extremes are bracketed by carriers that already ship, so nothing needs
    fixing — but do not script a hand-off assuming an exact 0.35s gap.
  - The join is generated into assets/marketing/_carrier_joined/ and is
    rebuilt whenever a part changes. It is not source; don't edit it.

  ANCHOR INTRO DELIVERY SPEC (now a SET, not one file — see §2):
  - ⚠ EXPECT TO BE TRIMMED, AND SAY SO IN THE DELIVERY NOTE. The generator
    only emits at 4/6/8/10s presets, so "5.5s" rounds to 10. Every intro
    delivered to date — the 7/27 original, deadpan, powerup and public —
    arrived at 10.005s against a 6.5s ceiling. This is now the expected
    path, not an incident. Masters are preserved as *_master_10s.mp4 so
    the trim stays reproducible; they are NOT read by the pipeline.
    Do NOT state a duration you have not measured: v1.5-era deliveries were
    described as "5.5s, NO TRIM required" while measuring 10.005s, and on a
    rotating set that is worse than it sounds — a rejected member drops
    silently and the set collapses toward one intro while appearing to work.
  - THE TRIM RULE (apply it yourself if you can): find where smoke fills the
    frame, set the out-point 0.6s later, set the in-point 6.0s earlier, and
    slide the window if it runs past either end.
  - ⚠ REFINED 2026-07-29: THE IN-POINT FOLLOWS THE AUDIO, NOT THE PICTURE.
    `arrival`'s master hard-cuts from a static desk to the Anchor at 1.667s,
    but its audio does not start until 2.0s. Cutting on the picture cut —
    the obvious choice, and what the rule literally says — would have opened
    the reel on 0.33s of digital silence, which is the exact autoplay-
    retention failure the head trim exists to prevent. So: find the picture
    cut AND the audio onset, and take the LATER of the two. Check this every
    time; two of the five intros to date have had a silent head, and it is
    invisible unless you measure it (a waveform look is enough).
  - THE TWO TRIMS DONE ON 2026-07-29 WERE DIFFERENT (IN 2.0 vs IN 0.0) from
    the same 10.005s delivery shape. Do not read any previous trim's numbers
    as the spec — they are a result, not a setting.
  - Duration 3.5–6.5s, hard-enforced. Anything outside the window is
    REJECTED by preflight; that member drops from the day's rotation.
  - EVERY member of the set must satisfy this whole spec. Preflight now
    validates all of them, not just the standard file, and a defective
    member is a hard FAIL rather than a silent drop.
  - NOT EVERY CLIP CAN BE TRIMMED INTO COMPLIANCE — and this is the one
    failure mode the numbers do not catch. `anchor_intro_powerup` was
    rejected outright. Swept frame-by-frame across every candidate
    out-point from 5.0s to 10.0s: the smoke is ALWAYS inside the phone,
    with the bezel and notch still in shot, and at ~7.0s the clip hard-cuts
    to a wide newsroom. There is therefore no window anywhere in the file
    that ends on a usable dissolve bed — it is a REGENERATION, not a trim,
    and no choice of in/out point rescues it.
    ⚠ It PASSED the luma-spread check (105 at out 6.0s, inside the ≤120
    band) because that check measures UNIFORMITY, and smoke on a phone
    screen is just as uniform as smoke filling the frame. Dissolving from
    it would have ghosted a handset outline through the UI body. A second
    check now flags a dark border (edge-vs-centre brightness: powerup 41%
    vs standard 117% / public 90% / deadpan 75%) — but it is a WARN asking
    for an eye check, not a substitute for one.
    WHAT TO GENERATE INSTEAD: the camera must push FULLY into the screen so
    the handset leaves frame entirely, as public and deadpan both do at
    4→5s. The delivered ending must be smoke edge to edge with no device
    visible anywhere in the frame.
  - Must END on full-frame smoke. The dissolve reads the final ~0.5s as its
    bed. The 10s master pulled the camera back OUT to the newsroom over its
    last 2.5s — a beautiful shot that is unusable as an ending, and the
    reason the trim exists. Do not "complete" the move; end inside the smoke.
  - Must OPEN on the gesture, with sound. The 10s master spent its first
    ~1.9s on a static Anchor over silence; that head was cut because a reel
    opening on a still frame and no audio bleeds autoplay retention. Start
    on motion, and have the audio up from frame 1.
  - Embedded audio REQUIRED — it is the only sound before the VO enters.
    END it at true silence (the assembler's dissolve fade assumes that); it
    may start hot.
  - Must survive a 1:1 CENTRE CROP (keeps y 420–1500 of 1920). ⚠ The band
    REMAINS BINDING even though the 1:1 output cut was retired (MKT-39
    addendum): the identity chip and every composition clearance are
    measured inside it, and a future 1:1 resurrect must not trigger a
    re-delivery of the whole fleet. Originally specified for the
    square cutdown. Keep the visor, the gesture and the phone inside that
    band; the top of the head may clip.
  - Same resolution/frame-rate spec as everything else (native 1080×1920,
    30–60fps). The current file is 720×1280 24fps and gets upscaled.

  BRAND MOTION DELIVERY SPEC — stinger + endcard motions (MKT-19, new in v1.7):
  - MOTIONS ARE TEXT-FREE. Never bake a wordmark, headline or date into one.
    Copy is rendered fresh at 1080×1920 over the motion at build time, which
    is what makes a headline change a string edit instead of a regeneration.
    A motion arriving with type in it cannot be used at all.
  - EXPECT 10.005s, as with the intros — the generator's 4/6/8/10s presets.
    That is FINE here and needs no trim: endcards contract for 10s, and a
    stinger uses only its first 3.0s. But it means the beat times you were
    briefed for will not be the beat times delivered, so state what you
    MEASURED, never what you intended. Every MKT-19 delivery was described
    as 4.0s/10.0s and every one arrived at 10.005s.
  - ENDCARD MOTIONS: the crack (the bolt snap) should land ~4.3s, and the
    clip must END fully static — the final frame is reused as the reel's
    opening frame. The delivered set lands 4.2–4.5s, which is fine; the
    assembler measures each one rather than assuming.
  - ENDCARD MOTIONS NEED A LEVEL-STEADY STRETCH BEFORE THE CRACK. On a
    short-carrier day the pre-crack audio is looped as a palindrome to bed
    the modals, so the window must not swing more than ~20 dB.
    ⚠ THE SPEC IS ABOUT AUDIO SHAPE ONLY (2026-07-29). `pro_alt` failed on
    its SOUND, not its visuals — "rings align and release" is a fine thing
    to look at. So the visual concept is free to be as interesting as you
    like, provided the audio holds roughly CONSTANT from 0 to ~4.0s and
    then cracks. State the intended audio shape in the delivery note; it is
    the half that decides whether a motion can bed, and it is invisible in
    a preview. A build-up
    concept — "rings align and release", anything that swells continuously
    into the release — has no such stretch BY CONSTRUCTION and will be
    dropped from short-carrier days. That is handled gracefully, not an
    abort, so a build-up is an acceptable delivery; just know it buys a
    motion that only plays on some days. Two build-ups in the same tier
    would be a hard preflight FAIL.
  - STINGER MOTIONS: must open on full-frame smoke and present a usable
    dissolve bed at 3.0s (it is crossfaded into the body). ONE transient
    only, and it must land before ~2.2s. A second beat after the lockup
    has faded out fires on an empty frame and reads as a pop — this is the
    `circuit` defect, corrected in the build with an audio fade rather than
    a regeneration, but do not rely on that: a motion whose hero beat is
    late, or which pulses twice, is fighting the timeline.
  - TIER MATTERS FOR ENDCARDS ONLY. Say which tier a delivered endcard
    motion is for. Pro motions read as vault/precision/institutional; free
    motions as open/tidal/inviting. They can never cross — the code will
    not allow it — so a motion delivered to the wrong tier is simply the
    wrong asset.
  - Embedded audio REQUIRED on both kinds; it is load-bearing (the stinger
    impact, the endcard crack and its bed).
  - Same resolution/frame-rate spec as everything else below.

  ⚠ FILENAME RULE — NAME THE DESTINATION, UNAMBIGUOUSLY (adopted 2026-07-29).
  A delivered file's name must say which SURFACE it is for, using the word this
  handoff already uses for that surface. MKT-21's four bodies were named
  `group_body_*` but meant CROSS-POST; "group" means the free/Pro rooms (tier
  2/4) everywhere else in this document, so the names said the opposite of what
  they meant and the assets were assessed against Pro-room rules for two full
  rounds before the mismatch surfaced.
  This is the FOURTH filename failure in this lane and the first of its kind.
  MKT-06's 2-byte web rename and MKT-16's `_pt_` were MANGLED names; MKT-19's
  `verif_endcard` was a NON-UNIFORM name. This one was well-formed, correctly
  spelled, and simply meant something else in our own vocabulary — so no
  automated check can ever catch it. Only the convention can.
  Use: public · cross · free · pro · verify. Not: group, room, tier, social.
  If a file serves two surfaces, name the requirement they share, not one of
  them — cross-post and public are one requirement, so `public_*` covers both.

  DELIVERY SPEC (every replacement file):
  - Resolution: native 1080×1920 (9:16). Current endcards are 720×1280
    and get upscaled — it works, but costs sharpness. This is the #1
    quality upgrade available.
  - Frame rate: 30-60fps (24fps gets frame-duplicated to 60; slightly
    steppy motion on the energy effects).
  - All-Day carriers: VO must FINISH (hit silence) by ~20.0s of carrier —
    the assembler hard-fades at 20.5s and anything still talking gets cut.
    (History: 17.8/18.3 originally → tightened to 17.0/17.5 when the
    Anchor intro pushed the VO start later → widened to 20.0/20.5 on
    2026-07-27 when the modal hold went 2.0→2.5s. The window was widened
    to fit the narration rather than cutting it a third time; both
    delivered carriers now pass wall-to-wall with nothing discarded.)
    Content after the VO is discarded by design.
  - Endcards: keep audio in the file, front-loaded, crack synced to the
    visual snap; final frame = settled lockup (it opens the reel).
  - After any swap, engineering runs `npm run reel:check` — a preflight
    that verifies all of the above mechanically (corrupt files, missing
    audio, durations, VO-chop risk, weak crack, resolution) before
    anything is assembled. Deliver to pass it clean.

  THE DATE CHIP IS NOW VERIFIED AGAINST THE FOOTAGE (MKT-18, 2026-07-28).
  Previous versions of this doc said the stamp "can never disagree with the
  on-screen data". That was an assumption, not a check: the assembler took the
  date from its argument, confirmed a body file with that name EXISTED, and
  burned the date over whatever those pixels were. Copy a body to another
  day's filename and you got a clean, correct-looking reel of the wrong day's
  board — which is exactly what happened on 7/28 while testing the intro
  rotation. Each renderer now writes the captured date INSIDE the body file
  and both assemblers read it back: a mismatch aborts, naming both dates.
  Nothing changes for you — no new asset, no new step. It does mean a reel can
  no longer be re-stamped to a different day by renaming its body, so if you
  ever want a past day rebuilt, ask for a re-render rather than a rename.
  STATUS: every CURRENT body carries its tag (all four re-rendered 2026-07-28
  evening and verified: allday/midday/evening 2026-07-28, verify 2026-07-27,
  each matching its filename). Bodies from earlier days still carry nothing —
  re-assembling one of those prints a note and proceeds exactly as before,
  which is the intended floor, not a defect.

  FILENAMES ARE LOAD-BEARING — `reel:check` now scans for near-misses.
  Every asset is read by EXACT filename from a registry. A name that is
  almost right is the worst case in this system, because nothing errors:
  the registry finds nothing, the previous week's file stays in place, and
  the reel builds and publishes looking correct. It has happened twice —
  a 2-byte endcard from a GitHub web rename (MKT-06) and
  `public_carrier_pt_.mp4`, which matched neither the joiner's `_ptN`
  pattern nor the orphan scan that exists to catch exactly that (MKT-16).
  Two guards now close the class:
  - a `_pt` name that is not `_pt<N>.mp4` is a hard FAIL;
  - a STRAY SCAN enumerates every filename the registries can produce and
    reports anything on disk that no registry reads. That covers all four
    near-miss shapes — endcard, stinger, carrier, intro — plus panel source
    art, and it closes the one genuinely silent hole: if BOTH the carrier
    and endcard of a kind were misnamed, the kind used to report a healthy
    "dormant, no assets delivered" and say nothing else.
    A stray is a WARN, not a FAIL — it breaks nothing today, it just means
    something you delivered is not reaching a reel. Deliberate exceptions
    (the rejected powerup intro, the not-yet-registered public carrier) are
    listed WITH their reason so the exemption stays visible.
  Practical upshot: if you deliver an asset and the next `reel:check` names
  it as unreferenced, the filename is wrong — not the file.

  Outputs land in assets/marketing/allday_reels/, midday_reels/,
  evening_reels/ and verify_reels/, and are pushed to GitHub after every run.

MKT-15 — PHASE 2, THE PUBLIC CUT. BLOCKED, and bigger than first scoped.
  The headline finding: MASKING DIGITS IS NOT SUFFICIENT. The body is a screen
  recording of the real app, and the live audit (every on-screen string run
  through the real lint engine at tier 1) found four BLOCKING vocabulary terms
  structurally present on all six modals — PICK, STRAIGHT, BOX, PLAY — plus
  session labels and state-code attributions. A public cut needs a RELABELLED
  capture mode, not merely a redacted one.
  This is a TIER MISMATCH, NOT A BUG. Those words are the sanctioned
  vocabulary for the paying subscribers the app is built for. The fix is a
  capture-mode override and NEVER an edit to the consumer UI.
  COPY IS SETTLED — the eight-slot public set is delivered and approved; see
  docs/mkt15_phase2_copy_brief.md. Notably slot 3 ships as "ANY ORDER", not
  "SET": the brief's character-count rule was a bad proxy for pixel width, and
  measured on the live modal the chip has 86px of content width against
  "ANY ORDER"'s 55px. Paired with "BEST ORDER" it teaches itself.
  THE REDACTION IS NOT A BLUR OF THE DIGITS. The look is extreme blur + the
  bolt, as ruled — but capture mode never RENDERS the real digits: it draws a
  placeholder block, blurs that, and lays the bolt over it. A blur or mosaic
  derived from the true pixels is recoverable by sharpening across only 1,000
  combinations, and a high-contrast blurred 3-digit block is often readable at
  a glance anyway. Drawing a placeholder makes the frame-by-frame Q1 pass a
  fact rather than a judgement about how much blur is enough. Nothing changes
  in what you supply.
  ⚠ STILL OWED FROM CONTENT: the three bolt decisions (fill, placement,
  scale+opacity) and bolt_mark.svg if it exists — only the 2048 PNG arrived.
  ⚠ ALSO WORTH AUDITING: the PLAN tab CONTENTS are unaudited. The renderer
  captures each modal at its DEFAULT tab and never clicks through, so only the
  tab label is exposed today. The day a tab-switch beat is added to the
  capture, an un-audited surface enters frame. Better to have the list first.
