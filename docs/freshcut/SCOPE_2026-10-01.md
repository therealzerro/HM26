## 1. What FreshCut is

A creator uploads or records a talking-head clip (a "body"). FreshCut wraps it in a broadcast package built for that creator alone and returns a finished, captioned vertical reel. Two things are sold: a **SHOW PACKAGE** (the kit: 5–10 intros, 5–10 stingers, 3–5 endcards, one identity chip, one bed, optional lower third; made once, revised once, refreshed quarterly) and an **ASSEMBLY SERVICE** (5/10/20 reels a month on credits). The client never opens an editor. The intake is nine wordless screens in ~90 seconds that resolve through a versioned lexicon into a five-slot prompt brief; the content agent writes the generation prompts from it; the operator generates; gates pass; the client approves; the worker assembles every reel after that automatically.

**⛔ Separate entity (plan, first line).** Separate repo, Supabase project, Stripe account, domain, handoff file and audit. HitMaster code is never imported; HitMaster know-how is (asset laws, rotation logic, gates). The first line of the first work order says this.

## 8. Risks

- **Asset production is the long pole, not code.** Phase 0's house kit is a ~25-asset build plus 45 glyphs plus 6 sounds before the taste test exists. The §10.4 mix (shaders for worlds/materials) halves the generated count.
- **iPhone media behaviour** can silently break S2, S7 and the reveal (Low Power Mode, audio unlock, PNG export). The Phase 1 exit criterion is an iPhone in Low Power Mode.
- **Likeness and body uploads create obligations** HitMaster never had. Keep S9 optional, store the minimum, write the deletion job before the first upload, and get the generative vendor's data-use terms in writing.
- **Name conflict.** Cheapest to resolve now; expensive after glyphs, domain and Stripe account carry it.
- **Taste-test leakage.** The eight house stingers are both the measuring instrument and the house kit. Version them with the lexicon.
- **No alpha from any video API.** Stingers that need transparency are keyed from black or rendered on the final background; this constrains the material slot for the stinger kind and belongs in the lexicon's conflict table.
- **Wildcard and skip paths** are cheap to spec and easy to forget; both are in the brief schema; both need a test.

### 10.1 Front-end mechanics (name card, video grid, audio, palette, long-press, framework)

**Name card → PNG (M3, the reveal).** Render the card as live CSS for the UI, but build the export as a dedicated canvas/SVG renderer (text, gradients, tiled noise rasterised in a 2D canvas after `document.fonts.load()`), with a DOM-to-image library only as a convenience layer. Reason: every foreignObject-based library serialises the node in isolation, so `backdrop-filter` (glass) has nothing behind it, web fonts must be inlined, any cross-origin image taints the canvas, and iOS Safari has an open "first export is blank" class of bugs (html-to-image #556 Aug 2025, #569 Dec 2025, unfixed). Library status today: html2canvas is dead (last publish 2022); html-to-image stalled (2025-02); modern-screenshot (2026-04) and dom-to-image-more (2026-09) are maintained; **@zumer/snapdom (2026-09-28) is the best try-first candidate**; satori is deterministic but has no filters, so it suits flat/paper/metal cards and not glass/smoke. iOS canvas caps: ~16.7 MP area and a per-page canvas memory ceiling, so export at ≤ ~2000×2000 CSS px and do not multiply by device pixel ratio blindly.

**Materials in CSS.** Glass = `backdrop-filter: blur()` with the `-webkit-` prefix (unprefixed only since Safari 18). Metal/chrome = multi-stop linear or conic gradient with `background-clip: text`. Neon = stacked `text-shadow`. Film grain = `feTurbulence` at 1–2 octaves or a pre-tiled PNG noise (GPU-heavy on phones otherwise). Paper = tiled texture with `mix-blend-mode: multiply`. For export, bake grain and paper as bitmaps and glass as a pre-blurred backdrop image. Smoke is the one material with no credible CSS form; it needs a short video or a shader (see 10.4).

**The 8-clip taste-test grid (S2).** Autoplay needs `muted` + `playsinline`; off-screen videos pause. **iOS Low Power Mode blocks even muted autoplay**, shows a native play overlay you cannot style, and `play()` rejects. Pattern: call `play()` on all eight, catch the rejection, and swap to one "Tap to preview" that calls `play()` on all eight inside the same tap (one gesture activates all). Eight muted inline videos at 360–540 px wide is routine on 2020+ phones; use `preload="metadata"`, `loop`, a `poster`, and mount videos only for the visible screen. Codec: H.264 MP4 (`main` profile, `yuv420p`, faststart) as the universal baseline; AV1 as an optional first `<source>` saves 30–50% but only hardware-decodes on iPhone 15 Pro and later. Skip WebM/VP9 and HEVC. Target 3–4 s at 480p, CRF 24–28, roughly 300–700 KB each, grid under ~4 MB total. Fallback for weak devices: one stitched 2×4 video cropped per cell with `object-position`, which keeps a single decoder busy.

**Tap-to-hear (S7).** One `AudioContext`, created and `resume()`d synchronously inside the first `pointerup`/`click` (WebKit does not count `touchstart`); decode all six samples up front and play buffers. The iPhone ringer switch mutes Web Audio in the default ambient session but not `HTMLMediaElement`; set `navigator.audioSession.type = 'playback'` where supported (Safari 17+, not Baseline) or simply use one `<audio>` element per sample and accept ~100 ms latency. The simpler route is fine for a 2-second preview.

**Logo palette (S4 tenth swatch).** node-vibrant 4.x (2026-01, ~20 kB, semantic swatches) is the pick. Convert swatches to OKLCH (culori) and bucket by chroma/lightness/hue band into the nine worlds plus "warm/cool neutral", keep hex internal only. Logos often have transparent backgrounds; composite onto an opaque fill first or the extractor counts white/black.

**Long-press labels (concept §5).** Every glyph `<button>` keeps a permanent `aria-label` (WCAG 4.1.2); the long-press reveal is visual only. Activate on `pointerup`, cancel if the pointer leaves (2.5.2), make the label dismissible and shown on keyboard focus (1.4.13). Implementation: Pointer Events with a 400–500 ms timer, `touch-action: manipulation`, `user-select: none`, `-webkit-touch-callout: none`, and `preventDefault` on `contextmenu` for Android (iOS never fires it). A visible "?" toggle that reveals all labels at once is cheaper and audit-proof; worth proposing to Ledger as the accessibility affordance.

**Framework.** For the nine-screen intake on its own, Vite + React SPA + Supabase JS is the lightest fit: no SEO, no SSR, and an Expo/React Native background transfers directly. The plan (§5.1) chooses Next.js for the whole web app (landing, dashboard, billing, admin), which is reasonable once the funnel pages exist; the intake can live as a route in that app. The decision is really D3 (hosting family), not the framework: Next.js on Vercel means Pro pricing from the first paying client (10.2); Next.js static-exported or Vite on Cloudflare Pages is $0. Either way, keep the intake a client-rendered state machine over nine screens with no server dependency except the final Edge Function call.

**iPhone gotchas, in one list:** Low Power Mode kills muted autoplay; `touchstart` never unlocks audio; the ringer switch mutes Web Audio; `backdrop-filter` and web fonts are lost or blank in foreignObject exports and the first call is often blank; canvas area and memory caps; `-webkit-backdrop-filter` still needed before Safari 18; no `contextmenu` event. Phase 1's exit criterion must be an iPhone in Low Power Mode, not a desktop browser.

### 10.2 Backend, hosting, uploads, consent, notifications, review flow, payment

**Supabase Storage + RLS (fits the plan's §5.2).** Free plan caps files at 50 MB and pauses projects after a week idle; Pro ($25/mo) lifts the cap to 500 GB per file, includes 100 GB storage and 250 GB egress. Resumable TUS uploads use a fixed 6 MB chunk through `tus-js-client`; use it for anything over 6 MB (every phone clip). For the anonymous intake and the test-reel upload, have an Edge Function (service role) create the row and mint `createSignedUploadUrl` tokens (2-hour validity) for server-chosen paths like `intakes/{brief_id}/{slot}.{ext}`. The client never picks a path and the bucket has no anon SELECT policy at all. Set per-bucket `file_size_limit` and `allowed_mime_types`; Storage trusts the declared Content-Type, so sniff magic bytes in the Edge Function or the worker. Insert-only intake table: RLS with `FOR INSERT TO anon WITH CHECK (status='pending')`, no SELECT policy, client sends `return=minimal`. Add Turnstile/hCaptcha and per-IP rate limiting in the Edge Function. Store the brief as JSONB with `lexicon_version` duplicated as a plain indexed column.

**Hosting.** Cloudflare Pages Free allows commercial use (500 builds/mo, unlimited static bandwidth, Pages Functions on Workers Free 100k req/day). **Vercel Hobby's fair-use terms restrict it to non-commercial use**, so the plan's "Vercel $0–20" line is really Pro at $20/user/mo from the first paying client. This matters for D3: Vercel + Railway is still the fastest path, but it is not the cheapest, and the web app is thin enough that Cloudflare Pages + Supabase Edge Functions would cost $0 and avoid a second runtime. The render worker is the thing that needs a real host either way (see 10.5).

**Likeness and privacy (practical, not legal advice).** The S9 upload and the body uploads need a release that covers: use of name, handle, likeness, voice, logo in the kit and derivatives; scope limited to the client's own channels, with portfolio use as a separate opt-in checkbox (plan rule NEW 1 already says never without written yes); an explicit disclosure that clips may be processed by named third-party generative tools and that no biometric templates are created; no digital replica beyond the approved kit; retention (bodies 30 days, reels 90 days per plan §7.2; source references deleted N days after kit approval); revocation prospective-only; client warrants footage and logo rights; sub-processor list. BIPA (Illinois) excludes photographs; Texas and Washington key on extracting a face template, which the plan does not do. Washington's My Health My Data Act defines biometric data to include facial imagery and is untested, so clear consent and a deletion schedule are the mitigation. If the generative tool computes face embeddings internally, get the vendor's data-use terms in writing. EU/UK: photos are special-category only when processed for unique identification; still provide a privacy notice, retention period, deletion on request, and DPAs (Supabase and Cloudflare both offer them). 2025 state laws (NY Fashion Workers Act, CA AB 2602) make vague digital-replica clauses unenforceable, so be specific.

**Notifications.** Resend free tier (3,000/mo, 100/day) covers all of Phase 1 and 2. Supabase Auth's built-in SMTP is 2 emails/hour and auth-only, so magic links must go through Resend's SMTP too. Skip SMS: A2P 10DLC registration fees and vetting outweigh any value at tens of clients a month.

**Approval flow (plan F5 / §8).** Copy the common denominator of Frame.io, Vimeo Review and Dropbox Replay: tokenised review link with no login, status enum `needs_review → changes_requested → approved`, versions stacked on one kit, visible watermark burned by ffmpeg ("PREVIEW · {handle} · v2") until approval, download disabled, 7-day signed URLs. Tables: `kit_versions(brief_id, v, preview_url, status, revision_note, created_at)`. Two buttons: Approve (writes `approved_at`, locks, unblocks CREATE MY REELS) and Request changes (textarea required, increments the revision count, one included round per plan §2.1 then upsell). Email the operator on each action.

**Payments.** Stripe's restricted-businesses list (updated 2026-09-22) does not touch motion-graphics or creative services for creators. Use Checkout Sessions created in an Edge Function with `brief_id` metadata (Payment Links cannot carry it reliably). Kit setup = one-time Checkout at purchase (plan F4); the three packs = subscriptions with Customer Portal; refresh = one-time. If a deposit model is wanted, Stripe's own deposit-then-invoice-balance pattern works.

### 10.3 Market, pricing band, delivery spec checklist, onboarding precedents, name check

**Landscape (2025–26 list prices).** DIY/template tier: Placeit $14.95/mo, Canva Pro ~$15/mo, Envato Elements $16.50/mo, Renderforest $9–69/mo. Stream shops (pre-made, no revisions): OWN3D single stinger $15–32, packages $49–81; Nerd or Die packs $10–30; Visuals by Impulse stingers $7–8. Fiverr/Upwork customs: stinger $20–50, lower third $5–25, podcast intro/outro kit ~$150, Upwork intro/outro bumper projects $300–800. Productized studios: AnimArts $200 / $500 / $900 / $1,500 at 1–6 weeks and 1–3 revisions (stinger only from the $500 tier); LadyOverlays €100 stinger, €350–800 packs. Nothing in the first three tiers is bespoke and coherent; the studios are, at 2–6 weeks.

**Where the kit sits.** Five uncoordinated Fiverr parts total $185–320 with no system coherence; studios with a stinger start at $500 and 2–3 weeks. A cohesive hand-built 5-asset kit in 3–5 days with one approval round is defensible at **$249–399 (anchor $299)**, with a **$449–499 Pro tier** adding source files, extra cuts and a second revision. Below ~$150 reads as Fiverr; above ~$500 you compete with studios offering AE files and 2–3 revisions. This is an input to D7 only; the plan's rule stands that prices are set after real production hours are known. The monthly reel packs have no direct comparable in this research (editors like Descript/CapCut are tools, not services); the nearest analogues are per-reel editing gigs, which the plan's per-credit model undercuts on consistency rather than price.

**What buyers complain about.** Templates: the same stinger shows up on other channels. Customs: stingers delivered without alpha (black background), wrong data levels on track mattes, revision caps, source files sold separately, loop seams. Note the plan's reels are 9:16 MP4 for social, so the OBS alpha problem only applies if a stinger is ever sold standalone; the kit as specified never needs alpha because the assembler composites it. That is a genuine simplification worth keeping.

**Delivery spec checklist (what buyers expect if assets are ever handed over standalone; the plan's §2.1 spec already covers the assembled case).** Intro: 1080p MP4 plus a ProRes master, 3–8 s, 9:16 cut, audio at −14 LUFS. Stinger: WebM VP9 alpha and ProRes 4444 if standalone, OBS transition point in ms, SFX baked plus WAV. Endcard: 20 s and 10 s versions, loop-safe, YouTube element footprints left blank, 9:16 variant. Chip: alpha in/hold/out, editable text version if offered. Bed: 60–90 s loopable WAV + MP3, seamless loop verified, 10 s sting, written licence. Universal: font and palette sheet, one ZIP with README, alpha fringe and loop seams checked before delivery.

**Onboarding precedents (supports the concept's M1–M3).** Pinterest, Netflix and Spotify all seed personalisation with image taps and no typing; Stitch Fix found image grids let people judge whole style faster with less fatigue. Typeform's 2024 report: forms with images/video show +120% completion, ≤6 questions best; Outgrow 2025: 3–7 question quizzes complete at 65–85%. Graus & Willemsen (RecSys 2015): choice-based elicitation needs less effort and yields more satisfying results than rating-based, which is the research basis for S2 being the strongest signal. Two cautions: Bosch et al. 2022 found asking users to *upload* images hurts compliance, so S9 must stay optional with its reward visible (the concept already does this); and Raja et al. (J. Retailing 2026) found name personalisation lifts satisfaction and spend but backfires when overused or tied to the ask, so the name card should not appear on the BUILD MY SHOW button itself.

**Name check (not legal advice).** "FreshCut" is crowded in exactly this space: FreshCut Interactive's gaming-creator clips app (freshcut.gg, updated 2025-11), Fresh Cut Creative Inc. (US TM serial 86012886, "production agency services", status unverified), Fresh Cut video production agency (UK), FreshCut Studios at freshcut.tv, plus barber-booking apps on .io/.app. freshcut.com has been registered since 1996. freshcutkits.com returned no RDAP record and may be available. ### 10.5 Render worker, job queue, transcription, in-browser recording, ffmpeg specifics, Stripe credits

**Worker host (plan §5.3 says Railway or Fly at ~$10–30/mo).** A polling worker is always-on by design; "scale to zero" only exists if a dispatcher starts a machine per job, which is a Phase 3 shape. Numbers (vendor pages, 2026): Railway $20/vCPU-month + $10/GB-month billed per minute of actual use, 100 GB ephemeral disk, no job-time limit, and a DB-polling service never sleeps, so expect ~$5 plan + $15–30/mo usage at ~50 jobs/day. Fly.io shared-cpu-8x/2 GB $17.55/mo but rootfs is capped at 8 GB and slow, so a 2 GB input plus mezzanines needs a volume ($0.15/GB-month) and `auto_stop_machines="off"`. Render is weakest CPU per dollar. A plain VM is the simplest: Hetzner CX33 4 vCPU/8 GB/80 GB NVMe ≈ €9/mo (post 2026-06-15 price rise) or DigitalOcean 4 vCPU/8 GB $48/mo, container under systemd, big local disk, nothing to fight. **Recommendation for "one worker, first fifty clients": Hetzner CX33 or Railway.** Fly only if the operator wants Machines later. (Feeds D3: the web app host and the worker host are separate decisions.)

**Queue.** The plan's SKIP LOCKED choice is right at this size. Claim in one short transaction (`UPDATE jobs SET status='running', locked_at=now(), locked_by=$1, attempts=attempts+1 WHERE id = (SELECT id FROM jobs WHERE status='queued' AND run_at<=now() ORDER BY priority, created_at FOR UPDATE SKIP LOCKED LIMIT 1) RETURNING *`), heartbeat `locked_at` every 30 s, and a reaper in the worker loop that re-queues `running` rows stale by 10 min while `attempts < 3`, else `failed`. Backoff via `run_at = now() + 2^attempts × 30 s + jitter`. Never hold the claim transaction open across the render. Supabase Queues (pgmq) gives visibility timeout and `read_ct` for free but still needs progress/output columns elsewhere; worth it only when fanning out to several workers. The worker reads Storage through the S3 protocol with project S3 access keys (server-only) streaming to disk; set the uploads bucket limit to 2 GB. Browser TUS: fixed 6 MB chunk, direct `*.storage.supabase.co` host, `parallelUploads: 1`, persist the tus fingerprint and resume on `visibilitychange` because iOS suspends JS in background tabs; files over ~500 MB on iPhone are reported flaky (tus-js-client #227), so show "keep this tab open" and expect retries.

**Transcription (plan §5.4 left this open).** Deepgram Nova-3 batch $0.0043/min with native word timestamps and a $200 free credit; OpenAI whisper-1 $0.006/min (word timestamps need `verbose_json`); AssemblyAI $0.15–0.21/h (page dated 2026-09-28). Local faster-whisper `small` int8 runs ~3–6× real time on 4 shared vCPU but competes with x264 for the same cores and needs ~2 GB RAM. **Recommendation: Deepgram as primary (~$0.02 per 5-minute body; 50 clients × 30 reels × 3 min ≈ $20/mo), faster-whisper small as the offline fallback.** Music flag (plan NEW 2): run YAMNet (TF-Lite, AudioSet classes) on the 16 kHz mono extract and flag when the "Music" score exceeds ~0.3 over ≥20% of one-second frames; inaSpeechSegmenter misses speech-over-music, inaVAMOS (2025) has a `speech+music` class.

**In-browser recording (plan §7.2, Phase 2).** Safari 14.1–18.3 records `video/mp4` H.264/AAC only; Safari 18.4 (2025-03) added WebM, fragmented MP4, HEVC/AV1. Chrome records WebM VP8/VP9+Opus by default with no duration or cues in the container, so the worker must always full-transcode (never remux) and apply `fps=30` for variable frame rate. Default bitrate ~10 Mbps makes a 5-minute take ≈375 MB; set `videoBitsPerSecond ≈ 6e6`. Request `{facingMode:'user', width:{ideal:1080}, height:{ideal:1920}}` and normalise with scale+pad because iOS may return landscape sensor dims plus rotation metadata. iOS Safari crashes building a giant Blob at 1–10 minutes: use `start(1000)` timeslices streamed into IndexedDB or straight into TUS, cap in-browser takes at ~3 minutes, route longer takes to upload. `<input type=file capture=user>` is a quality-unknown fallback.

**ffmpeg specifics (plan §7.3–7.6).**
- xfade/acrossfade require identical size, SAR, pix_fmt, fps, timebase, sample rate and layout. Pre-normalise every segment (`scale=1080:1920:force_original_aspect_ratio=decrease,pad=…,setsar=1,fps=30,format=yuv420p,settb=AVTB`; `aformat=sample_rates=48000:channel_layouts=stereo`). xfade offset = ffprobe'd length of the *normalised* predecessor − 0.3, never the source length.
- Silence trim: `silenceremove` touches audio only and causes A/V drift. Run `silencedetect=n=-40dB:d=0.7`, parse the boundaries, cut video and audio together with `-ss/-to`.
- loudnorm single-pass pumps; do two passes (measure with `print_format=json`, apply with `measured_*` and `linear=true`), once on the body at ingest and again on the final mix because the bed changes loudness.
- Ducking: `sidechaincompress` with the body as sidechain (threshold 0.05, ratio 8, attack 50, release 400) on a bed pre-dropped by 12 dB, then `amix=normalize=0` (amix halves levels otherwise; ffmpeg ≥4.4).
- Captions: ASS with `PlayResX=1080, PlayResY=1920`, Alignment=2, MarginV ≈ 420 (above the bottom ~480 px where TikTok/Reels UI sits), MarginL/R ≈ 90, ≤2 lines by capping ~30 chars per cue; bundle fonts with `fontsdir=` because Docker images lack fontconfig fonts.
- QA: `blackdetect=d=0.1:pix_th=0.10` on the final, fail on black >0.2 s outside intro/stinger. Provenance: `-movflags +faststart+use_metadata_tags -metadata freshcut_job=… -metadata freshcut_recipe_sha=…` plus the standard `comment` tag so VLC shows something.
- **The plan's "one filtergraph, no intermediates" should be relaxed:** for 1–6 minute reels, normalise body and kit assets to CRF 16 mezzanines (kit assets cached once per kit version), then one assembly graph. One extra body encode buys matched parameters, per-stage retries and low memory.

**Stripe (plan §5.5).** Checkout `mode=subscription` can carry the one-time kit-setup price as an extra line item, so F4 is one checkout. Webhooks: `checkout.session.completed`, `invoice.paid` (grant credits keyed by invoice id, idempotent), `invoice.payment_failed`, `customer.subscription.updated/deleted`. On failed renewal: Smart Retries run up to ~4 weeks; stop issuing new holds, let in-flight renders deliver, grant on `paid`. **Stripe Billing Credits do not fit**: grants apply only to metered prices with Meters, not flat subscription lines, and have no recurring grant or rollover. So the plan's home-grown `credits_ledger` is right. Shape: `credit_buckets(customer, amount, remaining, effective_at, expires_at = next period_end + 1 month)` plus an append-only ledger with `grant | hold | finalize | release | expire`; hold on enqueue with a ~2 h TTL, finalise on delivery, consume the earliest-expiring bucket. One-month rollover falls out of `expires_at`.
